## What Went Well

**1. BASE_FIGURE singleton pattern (ADR-18-01) held across all 8 stories without rework.**

Established in story 18-1: `BASE_FIGURE = make_subplots(...)` once in `app.py`, accessed via `_base_fig() = copy.deepcopy(BASE_FIGURE)`. Every subsequent story (18-3 through 18-6) added traces to their assigned subplot cell without touching the grid definition. The one attempt to use `go.Figure(BASE_FIGURE)` shallow copy (18-3) was caught in review and never recurred.

Winston (Architect): "This is the value of writing the ADR before the first story. The pattern was unambiguous from the start."

**2. Stub pattern for future overlays — wired and ready for Epic 20.**

`absorption_overlay(fig, df)` and `liquidity_overlay(fig, df)` both follow the same guard pattern: return `fig` unchanged when required fields are absent, activate transparently when Epic 20 fields arrive. No layout changes needed for activation. The review process caught the dual-rendering conflict with `add_volume_levels` and added a comment to prevent confusion in Epic 20.

**3. SQL injection guard caught early (18-2a).**

`_SAFE_IDENT` regex validation on exchange/symbol parameters before format-string interpolation into QuestDB queries. Caught in first review, applied cleanly. No SQL injection surface exists in the current data layer.

**4. Nested Bootstrap layout (18-6) solved the no-scroll problem elegantly.**

The previous two-row flat layout had a heatmap at 720px driving total page height to ~1070px — scrolling at 1080p. The nested-column restructure (left w=6 stacked sub-rows + right w=6 at 700px) reduced total height to ~770px with zero chart code changes. The insight — that Bootstrap structure solves the visual "rowspan" independently of Plotly's internal subplot grid — was clean.

**5. ob-cursor-symbol sentinel guard (18-2b) prevented a symbol-change race.**

On rapid symbol switch, the live_update callback could fetch ob data from the previous symbol's Redis cursor for the new symbol. The `ob-cursor-symbol` store sentinel detects this and skips the ob fetch for one tick. Caught in review, implemented correctly the first time after the pattern was described.

Murat (QA): "The sentinel pattern is also testable. If we ever add tests to this service, that's a good case to cover."

mrqdt (Project Lead): "The dashboard covers everything we planned for Epic 18 and the Vite retirement gives us a clean slate. No technical debt from the old TypeScript frontend."

## What We Should Improve

### Pattern 1: Incomplete `dropna` subsets — 3 of 8 stories

18-4 (`dropna` missing `close` for delta heatmap), 18-5 (`dropna` missing `ts` in bidask panel), 18-2b (missing explicit `if not last_ts` guard). Each time a new column is used downstream of a `dropna`, the column was not added to the subset.

**Root cause:** Adding columns to `dropna` requires tracking which columns are used in subsequent operations, not just the ones tested explicitly. The mental model of "I dropna'd buy_volume and volume so I'm safe" misses columns added later in the function.

**Action for Epic 20:** Add a convention to dev notes: *"When using `dropna`, always list every column used in operations below that line."*

### Pattern 2: Dashboard has no automated tests

All 8 stories used manual verification (container start → `curl localhost:8050 → 200`, visual inspection). Two deferred items call this out (D-18-6-1). Bugs that were caught in code review (ts NaN in bidask panel, close NaN in heatmap y-axis) would have been caught at development time if unit tests existed for the chart builder functions.

The chart builder functions (`build_candlestick`, `build_cvd_panel`, etc.) are pure functions: `DataFrame → go.Figure`. They are testable with `pytest` + assertions on `fig.data` length, trace types, and `fig.data[0].x` values.

**Action:** Write a `dashboard/tests/test_charts.py` covering empty DataFrame guards and non-trivial trace assertions for each chart builder. Target before Epic 20 starts.

### Pattern 3: Review false positives on `_base_fig()` — 4 of 8 stories

Multiple review agents across stories 18-3 through 18-6 flagged that "adding traces with row/col to a bare `go.Figure()` will fail." This is incorrect — `_base_fig()` returns `copy.deepcopy(BASE_FIGURE)` which IS a `make_subplots` figure with the full grid. The false positive was caused by agents not reading `charts.py` to see the `_base_fig()` implementation.

**Observation:** The current 3-agent review (Blind Hunter + Edge Case Hunter + Acceptance Auditor) reliably finds real bugs, but Blind Hunter is susceptible to false positives on internal conventions not visible in the diff. The triage step successfully dismissed these each time. This is working as intended, but worth noting as a calibration point.

### Pattern 4: `barmode` spec ambiguity (18-5)

Multiple review agents flagged `barmode="overlay"` vs `"relative"` as potentially wrong for the Bid/Ask panel. The correct answer (pre-negated bid bars + "overlay") required explanation in each triage. The spec AC said "ask bars above zero, bid bars below zero" but didn't explicitly state the pre-negation + overlay approach.

**Lesson:** When a spec mentions chart behavior that depends on a specific Plotly option interaction, state both the behavior and the mechanism in the AC. "Bid bars extend below zero using pre-negated values with `barmode='overlay'`" is more defensive than "bid bars extend below zero."

## Key Technical Decisions

**ADR-18-01: Shared subplot grid in BASE_FIGURE, separate dcc.Graph per panel.**
Each panel is a separate `dcc.Graph` with its own Dash callback. All figures are `copy.deepcopy(BASE_FIGURE)` and add traces to their assigned subplot cell via `row=N, col=M`. This avoids cross-panel callback dependencies and makes each panel independently cacheable.

**Bootstrap nested columns for visual layout (18-6).**
Plotly's `rowspan=2` in `make_subplots` specs applies within a single figure. For multi-graph layouts where the heatmap must visually span two rows, Bootstrap nesting achieves this without Plotly involvement: left `w=6` col with two stacked inner rows, right `w=6` col with heatmap at combined height (700px = 420 + 280).

**Stub activation pattern for Epic 20 overlays.**
`absorption_overlay` and `liquidity_overlay` are wired into `update_candlestick` and return `fig` unchanged when their fields are absent. They activate automatically when Epic 20 candle fields arrive without any callback or layout changes. The `liquidity_overlay` comment documents the dual-rendering conflict with `add_volume_levels` to prevent confusion during Epic 20 implementation.

**`_SAFE_IDENT` regex for SQL injection guard.**
Exchange and symbol parameters are validated against `^[a-zA-Z0-9_:-]+$` before interpolation into QuestDB SQL strings. This is the only user-controlled data path in the dashboard's data layer.
