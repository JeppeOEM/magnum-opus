## What Went Well

**1. Circuit breaker is pure and independently testable.**
`DailyLossCircuitBreaker` is a standalone class with no I/O — just arithmetic and a date comparison. The `on_circuit_breaker_trip` callback is injected, not hardcoded. This makes `test_circuit_breaker.py` straightforward: no mocking of the registry, bus, or file watcher.

**2. Stop-all deferred item (D-17-4-3) resolved as a side-effect.**
Story 24-1 required adding `deprovision_pubsub` to `stop_all` — which was exactly D-17-4-3. Combining these saved a separate future cleanup commit.

**3. Absolute USD cap is opt-in via zero-default.**
`max_order_notional_usd=0.0` means the cap is disabled by default and the existing percentage-based gate still works independently. Operators who don't configure the env var see no behavior change.

**4. 42 new tests in a single commit.**
Both epics were small and cohesive enough to implement together. The test count per story (roughly 8-14 each) is consistent with the project's TDD pattern.

---

## What Did Not Go Well

**1. No formal code review pass.**
Epic 24 was shipped without a dedicated code review (`bmad-code-review`). The story files document the acceptance criteria but no adversarial review pass was recorded. This diverges from the established story-review loop and means the standard security/correctness/memory check layer was skipped.

**2. Circuit breaker wired but effectively disabled until Epic 25.**
`DailyLossCircuitBreaker.record_pnl` receives `realized_pnl` from `handle_fill`, but `realized_pnl` is always `0.0` until Epic 25 lands. The circuit breaker is correctly wired but cannot trip in the current state. This is a known and documented limitation (story spec acknowledged it) but it means the primary safety net of Epic 24 is inert in production today.

**3. Epics 23 and 24 combined in a single commit.**
Combining two epics makes `git log` and `git bisect` harder to use. Future archaeology has to parse a large commit to understand what each epic contributed.

---

## Lessons Learned

**1. Wire the review loop even for small epics.**
Epic 24 has security-adjacent code (stop-all, circuit breaker trip) that benefits from adversarial review. Small epics should still run `bmad-code-review` before marking done.

**2. Document "wired but disabled" state explicitly in health endpoint.**
The `/health` response includes `circuit_breaker_tripped: bool` but nothing indicates that `realized_pnl` is always 0.0. Operators seeing `circuit_breaker_tripped: false` might assume the guardrail is active when it's not. A `circuit_breaker_effective: bool` field (or a log at startup) would clarify readiness.

**3. Keep epics in separate commits even when implemented together.**
One commit per epic makes the history readable. Use `--allow-empty` intermediate commits or just separate the staged files into two commits.
