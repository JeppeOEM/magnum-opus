## What Went Well

1. **Architecture symmetry.** KuCoin and Bybit converged on a parallel structure (`Adapter` → optional `mux/` → `exchange.Exchange`). The Epic 1 interface design held without modification.

2. **Production bugs caught by L3 tests — before production.** Two genuine correctness bugs found during test writing:
   - **2.2:** `resetAcks()` race — `Subscribe()` called immediately after `Connect()` raced with the goroutine's first iteration clearing `pendingAcks`. Fixed in production code.
   - **2.5:** `innerDone` reconnect contract — `pingLoop` closing the connection didn't signal `Reconnect()` (WS-level keepalive disabled), so `runSlot` blocked forever. Fixed via `innerDone` channel as third select case.

3. **Clock injection discipline.** Zero `time.Now()` violations in `internal/` across all 5 stories. The `make test-l1` grep ban held.

4. **MockWSServer pattern established.** In-process mock WS server defined in `exchange/kucoin/kucoin_test.go` (2.2), reused and extended in `exchange/bybit/bybit_test.go` (2.5). Pattern is now institutional.

5. **Adversarial code review value proven.** 10 meaningful patches applied across stories 2.4 and 2.5: goroutine leaks, nil panics, timer resource leaks, write-error-without-close, nil context guard. Real bugs, not cosmetic feedback.

---

## Challenges

1. **Story 2.3 code review skipped.** First process deviation in the project. The `tokenRenewalLoop` goroutine-lifetime-after-exhaustion defect is unreviewed and sitting in production code.

2. **Reconnect contract is the recurring hard problem.** Three separate stories hit non-obvious reconnect semantics:
   - 2.4: `runSlot` select-case ordering
   - 2.5: `innerDone` pattern (app-level pong close doesn't signal transport-level `Reconnect()`)
   - 2.3: `tokenRenewalLoop` exits on exhaustion, fresh connection has no running renewal

3. **ATDD scaffolds not used.** 0 of 5 stories had pre-implementation ATDD scaffolds. The red-phase was written alongside implementation, not before. The `resetAcks` race and `innerDone` issue might have been designed out earlier with a pre-implementation failing test.

4. **`coder/websocket` + `httptest.Server` incompatibility.** The WS library uses `http.Hijacker`; `httptest.Server.CloseClientConnections()` doesn't close hijacked connections. Required `connDropper` (sync.Once + chan) workaround in 2.2. Not documented in library. Found by trial and error.

5. **Goroutine resource lifetime class of errors.** `time.After` leak in `pingLoop` pong wait and write-error-without-close were both missed during implementation, caught only in review. These form a pattern: goroutine resources (timers, connections) not properly released on all exit paths.

---

## Key Insights

1. **L3 MockWSServer tests are the highest-leverage test tier for exchange code.** Both production bugs were caught at L3 and would not have been visible at L1/L2. The investment in the MockWSServer pattern pays off immediately.

2. **Adversarial review catches goroutine resource leaks consistently.** Reviewers focusing on resource lifetime found bugs the primary implementation pass missed in 2 of 2 reviewed stories. This is a repeatable pattern — make review non-optional.

3. **The reconnect contract must be designed explicitly, not emerged.** Every story touching connection lifecycle had a non-obvious reconnect edge case. In Epic 3, the coordinator will face the same class of problem around backpressure and writer failure. Design the contract before implementing.

4. **ATDD scaffold before production code would have surfaced the `resetAcks` race.** A failing test for "Subscribe immediately after Connect" written before any goroutine code would have forced the goroutine lifetime design to be correct from the start.
