## What Went Well

**1. TWAP close-vs-open timestamp invariant documented and tested.**
`TestAccumulator_CurrentBar_TWAP_CloseTimestampVsOpenTimestamp` documents a non-obvious API contract: pass `tsSecMs` (close time) to `CurrentBar`, then override `TsSecMs = barOpenMs` for the QuestDB row. The test includes the wrong-path case showing exactly what breaks if you pass `barOpenMs` directly. High-value test for future maintainers.

**2. Crash-marking pattern is explicit and tested.**
`TestAccumulator_CrashMarkingPattern` documents the intentional asymmetry: `acc1m`/`acc15m` get `IncrementGap` after `Reset`, `acc` does not. Both hunters flagged this as an anomaly; the test explains why it's correct.

**3. W-MON weekly anchor handled and tested with contrast case.**
The W-MON vs W-SUN distinction is non-obvious in pandas. The test explicitly shows W-SUN gives wrong weekly boundaries, confirming W-MON is correct for ISO-week-aligned bars.

**4. `_TF_INFO` as single source of truth.**
All TF routing (source table, resample freq, n-base-rows) flows through one dict. Python aggregation and Go storage are coupled through that single data structure — no duplication.

**5. `_aggregate_rows` test suite is comprehensive.**
307 lines covering OHLCV correctness, spread_high as max not first, mid_price_low as min not last, W-MON weekly alignment, single-print union, footprint merge, incomplete-window filter. Regressions in the aggregation logic will be caught.

## Challenges and Lessons

**1. `live_update` cursor regression — copy-gap across two call sites.**
`update_candle_store` correctly used `last_source_ts` when the problem was actively being thought about. `live_update` was then patched for the TF param but the existing `new_candles[-1]["ts"]` line wasn't re-evaluated. Lesson: when adding a parameter to one callback, scan all callbacks that share the same cursor state for the same update.

**2. Shutdown path didn't account for DEDUP-upsert semantics.**
The `Open == nil` guard for the shutdown flush is correct, but the root cause is that DEDUP-upsert makes the shutdown write semantically different from non-DEDUP tables — an empty partial can silently overwrite a complete row. Lesson: when a table has `DEDUP UPSERT KEYS`, every write path must consider whether it could race with another write at the same key.

**3. `sorted()` on price strings is always wrong.**
`_merge_single_print_levels` used `sorted(merged)` on string price keys — lexicographic order where `"9999.5" > "10000.0"`. Lesson: any `sorted()` on numeric-valued strings needs `key=float`.

**4. No callback-level tests — regression lived in `live_update` return value.**
`test_data.py` covers `data.py` internals thoroughly but there are no Dash callback tests. The cursor regression in `live_update` wasn't caught by the test suite. Consider adding callback unit tests (using `dash.testing` or by extracting pure functions from callbacks).

**5. Workflow was skipped — no story files created upfront.**
Epic 21 was implemented in a single session directly from the memory plan, with stories and sprint-status added retroactively. This is acceptable for tightly-scoped single-session work but means the sprint-status was stale during implementation. Added retroactively on 2026-05-16.
