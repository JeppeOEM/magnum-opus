## Code review findings

### Fixed during implementation

- `FlushHealthy` boundary condition: initially used `< windowSecs` (unhealthy only within window, exclusive). Test caught it — corrected to `<= windowSecs` (failure at exactly boundary age is still unhealthy).
- `RecordGap` story spec said `sync.Map` but spec code used `sync.Mutex` + plain map. Used Mutex since `GapHealthy` iterates all entries (sync.Map.Range would work but Mutex+map is simpler and matches the spec code exactly).

### Pre-existing issue flagged (not introduced by Epic 10)

- `questdb/questdb:latest` in `docker-compose.yml` violates the NFR1 pinning constraint. This predates Epic 10 — pin to an exact tag when you next touch infrastructure (e.g., `questdb/questdb:8.x.y`).

## Design decisions

- Aggregator uses `lastGapTimes map[string]int64` (keyed by "exchange/symbol") — supports per-symbol gap tracking; any symbol with a gap in the window drops the whole `gaps` health condition.
- Candle-service uses a single `lastFlushFailureUnix int64` — flush is a service-wide singleton (one flusher), not per-symbol.
- Both services update health in the existing 5-second polling goroutines — zero new goroutines, zero new tickers.
- `computeMinFeedState` returns 1.0 when no `aggregator_feed_state` series exist (no feeds configured yet) — correct: if there are no feeds there's nothing failing.
- Grafana dashboard uses datasource template variable (`${datasource}`) for easy swapping between Prometheus instances.
- Alert for `aggregator_health{condition="gaps"}` added (info/5m) — not in original architecture doc but necessary for completeness since the gauge was implemented in 10.1.
