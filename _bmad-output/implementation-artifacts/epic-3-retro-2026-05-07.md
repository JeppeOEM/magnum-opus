## What Went Well

### 1. Code review coverage: 100%
Every story went through the full three-layer adversarial review (Blind Hunter, Edge Case Hunter, Acceptance Auditor). This caught real issues — 36 findings across the epic — before they reached production.

### 2. Interface-first design held throughout
`StreamWriter`, `ILPWriter`, `SnapshotFetcher` — each writer was defined as an interface and tested in isolation before the coordinator existed. This pattern kept every story independently verifiable and made the coordinator composition straightforward.

### 3. `sleepFn` injection pattern
Injecting sleep as a function rather than using `time.Sleep` directly enabled deterministic tests with the static `MockClock`. Without this, tests would need real timers or complex mocking. The pattern was established in story 3-2 and held across all subsequent stories.

### 4. Backpressure design
The `snapReqs` channel + per-symbol `resultCh` (cap=1) design bounded memory and prevented snapshot storms under concurrent reconnects. Designed correctly in 3-1 and stayed stable through 3-5.

## Challenges

### 1. ATDD: zero adoption, two epics running
The Epic 2 retrospective committed to acceptance-test-driven development. Epic 3 had 10 stories (5 implementation + 5 code reviews). ATDD usage: zero. This is the second consecutive epic where the commitment was made and not followed.

**Impact:** Some code review findings — the `time.After` goroutine leak, the `defer cancel()` in a loop body, the stale snapshot path missing a gap marker — are exactly the kind of issues that failing acceptance tests would surface before review. Review debt accumulates instead.

### 2. `time.After` goroutine leak — recurring pattern
`time.After` was used incorrectly in `sleepWithContext` (coordinator), producing a goroutine leak when the context cancelled before the timer fired. This is the same class of bug caught in previous stories. The fix (`time.NewTimer` + `defer t.Stop()`) is known; the mistake keeps appearing in new code.

### 3. 36 code review findings across the epic
Volume breakdown: 5 patches applied, 11 deferred to `deferred-work.md`, 1 decision resolved (AC3 Redis drain → deferred to story 4.3). The review bar is appropriately high, but recurring patterns (timer leaks, error discarding) should not require review to catch.
