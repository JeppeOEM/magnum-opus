## Code Review Findings (Story 11.7)

### Fixed during implementation

- `logging.root.setLevel()` not called after second `basicConfig()` — stdlib log level stayed at INFO regardless of `LOG_LEVEL` env var. Fixed: added explicit `logging.root.setLevel(level)` after `basicConfig()` call.
- `add_indicators()` exception propagated uncaught out of `on_bar()` — would silence the event loop for that symbol permanently. Fixed: wrapped in `try/except Exception` with WARN log.
- **Critical correctness fix — NaN guard permanently blocks handlers**: original `df.isnull().any().any()` checked ALL rows and ALL columns. Once pandas-ta appends indicator columns (e.g., RSI_14), the warmup rows (first 13 bars) have NaN in those columns forever. Result: the NaN guard would fire on every call indefinitely, blocking the signal handler permanently once any indicator was added. Fixed: `df.iloc[-1:].isnull().any().any()` — checks only the current (last) bar.
- Missing `@pytest.mark.l1` markers on test functions — AC6 violation. Fixed: added to all 5 test functions.
- `add_indicators()` docstring missing warning against local `df` reassignment. Fixed: added IMPORTANT note explaining that `df = df.dropna()` has no effect on `self._dfs`.
- `structlog.stdlib.add_logger_name` removed from `_configure_logging()` — `PrintLoggerFactory` produces `PrintLogger` which lacks `.name` attribute required by the processor.

### Deferred to later epics

- `sys.exit(1)` inside ASGI lifespan — spec-mandated; uvicorn handles `SystemExit` cleanly.
- `BusManager.is_alive()` returns True when healthy-but-idle (zero strategies registered, pre-Epic 12) — by design until strategy threads exist.
- `pandas-ta>=0.3.14b` has no upper version pin — maintenance item for Epic 15+.
- No test for `add_indicators()` override/exception path — Epic 15 will exercise concrete strategies.
- Heartbeat thread sends SIGTERM via `os.kill` — pre-existing Story 11.6 design; acceptable for MVP.

## Discovered implementation gaps (runtime vs spec)

### QuestDB API (11.2) — three surprises

1. **POST /exec doesn't work for DDL.** The story spec showed `POST /exec` with form body. QuestDB 8.2.1 only accepts `GET /exec` with query params for DDL — POST returns "Method not supported". Updated `schema.py` to use `httpx.Client.get()`.
2. **HTTP 200 on DDL error.** QuestDB returns HTTP 200 even when a DDL statement fails (e.g., malformed SQL), with `{"error": "..."}` in the body. `raise_for_status()` alone is insufficient — added explicit check for `"error"` key in response JSON.
3. **No /health endpoint.** QuestDB 8.2.1 returns 404 on `/health`. L2 test readiness probe uses `GET /exec?query=SHOW TABLES` instead.
4. **`column` is a reserved SQL keyword** in QuestDB. L2 test that introspects column types uses `SELECT "column", type FROM table_columns(...)` with double-quoted `column`.

**Implication for Epic 12:** Any QuestDB ILP or REST interaction should be tested against a real container — don't trust the spec's assumed API behavior.

### Pydantic v1 vs v2 (11.1)

Story snippet used inner `class Config:` (Pydantic v1 style). `pydantic-settings` 2.14.1 requires `model_config = {...}` (v2). Adapted without issue, but spec snippets should use v2 syntax going forward.

### Starlette 1.0 TestClient lifespan (11.7)

`with TestClient(app) as client:` triggers ASGI lifespan startup via `portal.call(self.wait_startup)` inside `__enter__`. Without the context manager, requests route through the ASGI app with `http` scope only — lifespan does NOT run. Tests that need to control `_bus_manager` directly must use the no-context-manager pattern.

### Missing deps in requirements-dev.txt (11.6)

`pandas` and `httpx` were not in `requirements-dev.txt` — they are runtime deps but were installed only via `requirements.txt`. For clean dev environment setup, both should be in dev requirements too. Not fixed in this epic (deferred to Epic 12 housekeeping).

## Design decisions

- **Pydantic v2 `model_config` dict with `# type: ignore[call-arg]`**: mypy cannot statically resolve that pydantic-settings will supply required fields from the environment. The ignore is justified with an inline comment.
- **`_REDIS_URL_PATTERN` module-level compiled**: compiled once at import time, not inside the processor on every call — identical behaviour, avoids repeated regex compilation.
- **BusManager overflow drops 2 items**: when `qsize >= maxsize`, we drop one item for the GapMarker and one for the real event. The initial conditional second-drop was dead code.
- **NaN guard checks only `df.iloc[-1:]`**: checks only the most-recent bar, not the entire rolling DataFrame. Indicator warmup NaN in early rows is structural and permanent — checking the full DF would permanently block handlers.
- **`run_subscribe` uses `ThreadPoolExecutor` context manager**: Python 3.9+ `__exit__` calls `shutdown(wait=True, cancel_futures=True)`, preventing indefinite block after timeout.
- **Barrier `_fired` pruning**: entries older than `bucket_ts - 2 * timeout_ms` are pruned on each `_fire_bucket` call — bounds memory to `ceil(2 * timeout_ms / tf_ms)` entries (typically 1–2).

- PaperExchangeClient: paper fill requires reading live tick stream from Redis; must handle empty stream without rejecting orders

**Recommended story order:** 12.1 → 12.5 → 12.2 → 12.3 → 12.4 (implement paper client before WS feed so order worker can be tested end-to-end with paper mode before adding live mode complexity).
