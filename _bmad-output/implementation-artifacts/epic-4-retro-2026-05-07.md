## What Went Well

### 1. FR33 caught before it would have burned a production deploy

The SIGTERM-during-startup-gate bug (story 4.3) was a real correctness violation: a clean shutdown during the 90-second startup window would have exited 1 instead of 0, leaving Docker Compose in a restart loop with no log distinguishing "startup failed" from "shutdown was requested." Review caught it. The fix was one line in `runStartupGate`.

### 2. ARC9 — credential safety held end-to-end

`slogredact.Handler` is initialized before any other package logs, enforced by structure (`config.Load()` writes directly to stderr before slog exists; everything after uses `slog.Info/Error`). The `init()` ban in the Makefile catches any future drift. The `Credential` sealed type (from Epic 1) + `LogValue()` + key-based redaction in `slogredact` gives three independent layers of credential safety.

### 3. distroless runtime image

Using `gcr.io/distroless/static-debian12` rather than `alpine` for the runtime stage eliminates an entire shell and package manager from the attack surface. No `sh`, no `apk`, no standard tools that an attacker could leverage post-exploit. The non-root user constraint is enforced at the Dockerfile level (`USER nonroot:nonroot`), not just documented.

### 4. Release pipeline gated correctly

The `workflow_run` trigger on `release.yml` means a broken commit cannot be published by tagging it — the CI run must have already passed on that commit's SHA. Two review patches hardened this: the `startsWith('v')` guard correctly matches tag names (not full refs), and `fetch-depth: 0` prevents `git describe` failures on shallow clones. These are exactly the kind of silent failures that would surface on the first real release.

### 5. Test count exceeded target at L5

The spec asked for 18 live tests. The implementation delivered 20 (10 KuCoin + 10 Bybit). More importantly, the credential guard uses `TestMain` to exit with a clear human-readable message if env vars are missing — not a confusing authentication failure buried in test output.

## Challenges

### 1. ATDD: third consecutive epic without adoption

Epic 3 action item A1 was "write the AC test first — no exceptions." Epic 4 result: zero ATDD. Every story was implementation-first, with tests written after. The pattern is now three epics long and is clearly structural, not a capacity issue.

**What it cost this epic:** The `FeedState.Set(0)` on sequence gap (4-1 patch) and the `TicksTotal` on ctx-cancelled write (4-1 patch) are both bugs that a failing AC test would have surfaced before any code was written. The test would have said "FeedState should not change on a seq gap — is this a connectivity event?" Instead they surfaced in adversarial review.

### 2. `nowFn` injection added post-hoc to bypass a ban

The `time.Now()` ban in the Makefile catches direct calls in `internal/`. `httpapi/server.go` called `time.Now()` directly in `handleHealth`. The fix — add a `nowFn func() time.Time` field set to `time.Now` (function reference, not call) — is correct and passes the grep, but it was added reactively in review rather than designed in. The right time to notice this was when the ban was written, not when the code was written.

### 3. gapwindow never wired to coordinator

`gapwindow.Window` is allocated in `main.go` and passed to the HTTP server, but nothing ever calls `win.Add()`. The `gap_count_24h` field in `/health` will be 0 for the entire process lifetime. This is a coordination gap across epics: coordinator workers detect internal gaps and write to Redis/QuestDB, but the path back to `gapwindow` was never closed. Wiring it requires adding `gapwindow` as a coordinator dependency — a refactor deferred out of scope. The `/health` endpoint has a silent lie in it going into production.

### 4. Coverage gate not expandable to new packages

Adding `httpapi` and `slogredact` to the 95% coverage gate caused failures because `httpapi.Start()` (the real listener) is never called in unit tests — 0% function coverage on that path. The gate was reverted to the original three core packages. The new packages still run in `test-l1` (failures would be caught), but they have no minimum coverage floor. The underlying issue is that `Start()` is not separately tested; the `Handler()` method is the correct test entry point and has good coverage, but the coverage tool counts functions, not just the tested paths.

## Summary

Epic 4 is complete. The aggregator is deployable via Docker Compose, published via GitHub Actions on a semver tag (gated on CI pass), observable at `/health` / `/version` / `/metrics`, and validated by 20 live exchange tests before any release is tagged. The credential-sanitizing logger and `slogredact` handler ensure no API key can appear in logs at any level.

The one meaningful gap going into production is `gap_count_24h` silently reporting 0. Everything else — startup gate, SIGTERM handling, non-root runtime image, release pipeline gating — is correct. The system is shippable.
