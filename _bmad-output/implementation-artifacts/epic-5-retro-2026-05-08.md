## What Went Well

**Circular-import discipline (5-5):** The orderbook mirrored consumer types locally rather than creating a shared-types package, eliminating import cycles while keeping the package pure. This pattern will serve every story in Epic 6 that builds on the OB.

**L1/L2 test split:** Every compute package (accumulator, features, backoff, orderbook) is zero-IO with injected dependencies. The full L1 suite runs in milliseconds. Epic 6 feature testing will be straightforward as a result.

**Delivery completeness:** All 7 stories done with no scope cuts. The composition root (main.go) uses one shared ticker goroutine for the whole process — correct architectural choice that was preserved across all stories.

**WAL auto-recovery:** The probe-and-resume loop with bounded WAL buffer is production-grade resilience. Not a shortcut taken.

## Challenges and Patterns

### 1. Schema Spec Divergence (Story 5-3)
- **What happened:** Story spec stated "67 columns." Implementation correctly produced 76 columns based on `project-context.md`. The divergence came from the Python-era design not reflecting Go candle service additions (best_bid_open/close, full depth pairs, ofi_l1, is_partial).
- **Impact:** Low (agent caught it and implemented correctly). But a less careful agent would have created a broken DDL.
- **Root cause:** Story specs were not updated when the final schema was finalized. `project-context.md` was the authoritative source, the story spec was stale.
- **Lesson:** Story creation must cross-reference `project-context.md` for concrete values (column counts, field names, env var names). Never copy counts from epics verbatim if the service spec has been updated.

### 2. Prometheus/promauto Violation (Stories 5-6 → 5-7)
- **What happened:** Story 5-6 introduced `promauto.NewCounter`, which registers with `prometheus.DefaultRegisterer` — explicitly forbidden in `project-context.md` in bold. The violation was not caught until Story 5-7's adversarial review.
- **Impact:** Required a complete metrics rework in 5-7 (new `internal/metrics/` package, wiring in main.go).
- **Root cause:** The dev agent did not read the critical rules section of `project-context.md` before implementing metrics in 5-6.
- **Lesson:** Critical rules in `project-context.md` (forbidden patterns, required patterns) must be checked at story start — not discovered at review. The adversarial review caught it, which validated the review process, but earlier detection is cheaper.

### 3. Code Review Findings in 5-7 (Four issues)
- **What happened:** Adversarial review of 5-7 found: (1) HTTP handler data race (`Handler` mutated after `ListenAndServe`), (2) `redactAttr` not recursing into `slog.GroupValue`, (3) `QuestDBWriteLatencyMs` histogram never observed, (4) weak per-symbol metric test.
- **Impact:** All four fixed before story marked done. The data race would have been a real production bug.
- **Root cause:** Mixed: (1) architectural — the two-server design was inherently racy; (2) implementation oversight — group recursion and histogram wiring; (3) test coverage gap.
- **Lesson:** For HTTP server setup, "start after all state is ready" is simpler and safer than "start early and swap handler." Credential-redacting handlers must handle all `slog.Attr` kinds including Group.

### 4. go mod tidy Initialization Sequencing (Story 5-1)
- **What happened:** `go mod tidy` had to be run twice during project initialization — once before source files (stripped deps), once after (restored deps).
- **Impact:** Minor. Debug log captured it.
- **Root cause:** Standard Go module initialization behavior when `go mod tidy` is run on an empty module.
- **Lesson:** Document Go module initialization sequence in project-context.md for future service creation.

## Key Insights

1. **`project-context.md` critical rules need active enforcement at story-start.** The promauto violation shows that bold warnings in a context file don't prevent violations if the agent starts coding before reading them. The fix is behavioral: check forbidden/required patterns first.

2. **Story specs can drift from implementation specs.** The epics were written early; `project-context.md` is the living source of truth. When they diverge, `project-context.md` wins — but ideally stories are created with current values.

3. **Adversarial review catches things unit tests don't.** The HTTP data race, redactAttr group handling, and unobserved histogram were not unit-testable from story ACs. The adversarial review is earning its place.

4. **Pure packages pay forward.** Every story in Epic 6 will benefit from the zero-IO, clock-injected design established in Epic 5. Investment in testability compounds.
