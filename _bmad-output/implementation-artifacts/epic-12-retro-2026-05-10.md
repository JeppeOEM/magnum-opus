## Code Review Findings — Patterns

### The dominant pattern: Silent Data Corruption

Every HIGH-priority finding across Epic 12 was a bug that **ran without exception but produced wrong data or wrong behavior**. This is the hardest category of bug to catch in standard TDD.

| Story | HIGH Finding | Silent failure mode |
|---|---|---|
| 12.1 | Stale timestamp after retry sleep | 401 on 2nd/3rd retry when exchange window is ±5s; only fails under slow network or heavy load |
| 12.1 | Stop direction inverted (`"down" if buy` → should be `"up" if buy`) | Wrong stop-loss direction placed on exchange; order placed, position not protected |
| 12.3 | ILP missing `ts_placed`, `ts_exchange` from columns dict | Timestamps silently absent from QuestDB; fields present in schema but always null |
| 12.3 | ILP missing `market_type`, `fee_currency`, `signal_type` SYMBOL columns | Same — columns null; downstream queries/filters on those fields return no results |
| 12.3 | `ts_placed` in milliseconds instead of microseconds | Timestamps off by 1000×; QuestDB stores wrong values, Grafana shows wrong times |
| 12.5 | `_simulate_fill` background task swallows all exceptions | Paper fills that error in `on_fill` silently disappear; position ledger never updated |

**Insight:** The "silent data corruption" class of bug is invisible to unit tests that only assert on return values or call counts. It requires adversarial review that specifically asks "what happens to each field in the output?" and "what can silently fail?"

### Recurring theme: Schema completeness vs API correctness

Story 12.3 had the most review findings (8 action items). The root cause was writing ILP code that correctly invoked the `Sender` API but got the schema wrong — missing columns that were in the DDL but not in the `symbols`/`columns` dicts passed to `sender.row()`. QuestDB accepts the partial write with no error.

**Fix pattern for Epic 13:** When writing ILP code, cross-reference every column in the DDL against the `symbols` and `columns` dicts before claiming the story is done. Add a checklist item to the ILP write task.

### Story 12.4 highlights: Fragile extraction removed

P2 (HIGH): `_extract_ilp_addr` was a fragile hostname-parsing function that failed for bare hostnames. Resolution was to remove the function entirely and change the signature to accept `questdb_ilp_addr` directly. Simpler is safer — don't parse what you can receive pre-parsed.

### Story 12.5 highlights: Background task discipline

`asyncio.create_task()` exceptions are silently swallowed unless the task explicitly catches them. Any background task that performs I/O must wrap its body in `try/except Exception` with a named error log. This is the Python async equivalent of goroutine panic recovery — it must be a non-negotiable pattern.

## Design Decisions

- **ExchangeClient as `typing.Protocol`**: Structural typing (not ABC inheritance) enables `PaperExchangeClient` to satisfy the protocol without importing the base class. Transparent swap in `OrderQueueWorker.__init__` based on `paper_trading` flag.
- **`place_order` returns `PlacedOrder` immediately + background fill task**: Paper client mimics the live client's interface exactly. The fill comes through `on_fill` callback in both modes.
- **QuestDB write BEFORE `open_orders` dict update**: Crash invariant for Epic 13 reconciliation. If crash occurs between ILP write and dict update, QuestDB has the placed order; reconciliation repopulates correctly.
- **Bounded `_seen_fill_ids` dedup set**: `set[str]` bounded via `deque(maxlen=10_000)` for LRU eviction. Prevents unbounded memory growth on long-running processes.
- **`detect_orphaned_orders` never cancels**: No auto-cancel invariant enforced by test assertion. The function's contract is notify-only; operator decides action.
- **Optimistic paper fill**: When ticks are present but no tick crosses the limit, paper client fills anyway at limit price. For paper trading simplicity — avoids the complexity of orders remaining open.

## Preparation for Epic 13

Epic 13 delivers: startup reconciliation (13.1), file watcher and strategy auto-load (13.2), kill switch integration, and production hardening.

**Dependencies satisfied by Epic 12:**
- `ExchangeClient` protocol with `get_open_orders("")` — used by 13.1 reconciliation
- `OrderQueueWorker.restore_open_order()` — called by 13.1 to repopulate in-memory state
- `detect_orphaned_orders()` in `reconciliation.py` — partial reconciliation pattern; 13.1 expands this into full startup reconciliation
- `order_events` QuestDB schema with `status` column — 13.1 queries `WHERE status NOT IN ('filled','cancelled','rejected','failed')`
- `order_alerts` QuestDB schema — 13.1 writes to it for unresolved discrepancies

**Key technical risks for Epic 13:**
- **L2 crash-recovery test** (13.1): The most complex test in the project — needs process kill, container restart, state verification. Spike testcontainers `DockerContainer.stop()`/`start()` pattern before writing the story spec.
- **`detect_orphaned_orders` API change**: Story 12.4 function accepts `exchange` as explicit param; 13.1 full reconciliation may need to restructure the signature. Review before implementing.
- **Force-subscription** (13.1 AC2): Symbols from open positions that aren't in `subscribe()` must be injected into the event bus routing. This requires access to bus internals — understand the coupling before implementing.
- **File watcher hot-reload** (13.2): `importlib.invalidate_caches()` + `sys.modules` removal is tricky; test the module reload sequence carefully, especially with circular imports.

**No significant discoveries requiring Epic 13 plan changes.** The plan is sound and the dependencies are all in place.
