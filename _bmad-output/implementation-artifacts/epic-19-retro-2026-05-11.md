## What Went Well

**1. Pure function architecture in `features/` package held consistently.**
Every signal group was implemented as a zero-IO, nil-safe pure function in `features/`. This made L1 testing fast and reliable, and kept `accumulator.go` as a thin orchestrator. No story deviated from this pattern.

**2. Additive migration discipline.**
All 5 migrations used `ALTER TABLE ADD COLUMN IF NOT EXISTS` with no destructive changes. Migration 007 landed cleanly on top of 006. Zero schema conflicts across the epic.

**3. Review cycle caught real bugs every story.**
No story was clean on first review. The adversarial review process found bugs that would have affected data correctness: cascade `buyVolume` not persisted (19-1), `max` variable shadowing (19-3), combined AND write gate suppressing valid fields (19-3, 19-5). All fixed before merging.

**4. Consistent nil guard pattern emerged and stabilised by 19-3.**
By story 19-3 the team landed on: *combined AND guard for grouped nullable fields in QuestDB writer and pubsub publisher*. Stories 19-4 and 19-5 followed this pattern on first attempt (19-5's gate was too broad — caught in review — but the intent was correct).

**5. test coverage escalated story-over-story.**
19-1 had sparse accumulator tests. By 19-4/19-5, accumulator integration tests were added proactively as part of implementation, not as a review patch. This trajectory is the right direction.

## Challenges

**1. Write gate scope was wrong in 3 of 5 stories.**
19-2: single nil check instead of combined AND. 19-3: same. 19-5: combined AND too broad (all 6 fields gated together, so CumDelta=nil suppressed FootprintDeltaDivergence). Root cause: no clear documented convention at epic start. Fix: convention now established — use per-group combined AND guards, never cross-group.

**2. State persistence reliability in accWriter required multiple patches in 19-5.**
Three separate persistence issues: cancelled context on shutdown (P3), Reset() not persisting zero (P4), and CVD not clearing on gap events (P2). These share a root cause: `accWriter` has growing cross-bar state but no systematic approach to lifecycle (init, gap, reset, shutdown). As state grows, each new field requires separate reasoning about each lifecycle event.

**3. Missing accumulator integration tests were a recurring review finding.**
19-1, 19-2, 19-3 all had review patches adding missing `accumulator_test.go` coverage. By 19-4 and 19-5 these were added proactively, but the gap in the first three stories created more review cycles than necessary.

**4. `prevClose` persistence not specified in 19-5 spec.**
The spec defined Redis persistence for `cumDelta` but not `prevClose`. This means the first bar after service restart produces no `CVDDivergence`. This is a designed limitation but worth noting — it came up in review and was deferred with rationale.

---

## Key Insights

1. **When adding new cross-bar state to `accWriter`, enumerate all lifecycle events up front:** gap event, Reset(), shutdown/persist, startup restore. Missing any one creates a persistence bug.

2. **Write gate convention:** use combined AND guards scoped to the *natural null group* (all fields from one signal group, or all fields that share the same nil condition). Never cross groups in one gate.

3. **Accumulator integration tests belong in the story, not the review.** The pattern "add a few Apply() calls, call CurrentBar(), assert fields are nil/non-nil/specific values" is cheap and catches wiring errors before review.

4. **The `features/` pure function architecture scales well.** Five signal groups, each with their own file, each with their own test file. Adding a 6th group in a future epic requires only a new file pair and a single call in `CurrentBar()`.

5. **Parser/flusher column ordering.** The `parseCSVRow` function in `flusher.go` uses named column lookup (not positional), so new columns can be added in any order. However, `row.go` struct field order should track the DDL for readability even though it's not functionally required.
