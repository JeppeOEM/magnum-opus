## What Went Well

**1. FIFO cost-basis is a clean pure function with no I/O.**
`_update_position` and `_CostBasisTracker.record` are arithmetic-only functions with no database or network calls. They're fully testable with just numbers — no mocking of the registry, bus, or file watcher required.

**2. Circuit breaker became functionally active immediately.**
As predicted in the Epic 24 retrospective, wiring `realized_pnl` into `DailyLossCircuitBreaker.record_pnl` (story 25-2) activated the guardrail that was built but inert in Epic 24. The separation was clean — Epic 24 built the infrastructure; Epic 25 provided the data.

**3. `restore_position` included as a forward-looking hook.**
Story 25-1 included `restore_position(symbol, qty, avg_price)` even though the Epic 13 reconciliation path (D-13-1) isn't yet implemented. The method is functional and ready — cost-basis state can be restored from QuestDB data when Epic 13 revisits crash recovery.

**4. Backtest isolation maintained correctly.**
`_CostBasisTracker` in `backtest/writer.py` is an intentional duplicate of `_update_position` rather than an import. This preserves the "no cross-service imports" rule for the backtest package and keeps the backtest path independently deployable.

**5. Slippage computation delivered in the same story.**
Story 25-2 computed slippage (fill price deviation from limit) as part of the same ILP write. This was already in the story spec and required no extra story since the data was at the same call site.

## What Did Not Go Well

**1. Wrong guard condition: `cur_avg > 0` instead of `cur_qty > 0`.**
The initial implementation used `if cur_avg > 0` as the gate for P&L computation. The correct gate is `if cur_qty > 0`. The bug: `restore_position(symbol, qty=1.0, avg_price=0.0)` would create a legitimate open position with a zero average price (e.g., tokens acquired at zero cost, or avg_price not yet known). With `cur_avg > 0`, the guard incorrectly zeroed out P&L on the next closing sell. Found in code review — P1 patch.

**2. `restore_position` docstring said "No-op stub".**
The method stores `qty` and `avg_price` and is fully functional from day 1. The docstring said "No-op stub until D-13-1 is revisited," which is misleading — it implies the method can be ignored or removed. Found in code review — P2 patch.

**3. Four story AC tests missing from initial commit.**
The initial 42-test commit was missing: `test_handle_fill_loss_close` (AC 25-2: `realized_pnl < 0` via handle_fill), `test_restore_position`, `test_restore_position_then_sell_uses_restored_avg`, and `test_circuit_breaker_writes_correct_pnl` (asserts exact P&L value written, not just that `is_tripped()`). All four were explicitly in the story acceptance criteria. Found in code review — P3–P5 patches.

## Lessons Learned

**1. Guard position state with qty, not price.**
`cur_qty > 0` is the correct check for "is there an open position." The average price could legitimately be 0 (zero-cost token, uninitialized after restore, or edge cases in paper trading). Any check of the form `if cur_avg > 0` is a code smell when the intent is to detect an open position.

**2. Story ACs should become a test checklist before implementation.**
Epic 25 had four explicit AC test cases (buy/sell P&L scenarios, restore_position behavior, circuit breaker integration). These should be transcribed into test function stubs before writing the implementation, so none are missed in the initial commit.

**3. Functional stubs should not be called stubs.**
If a method does real work (mutates state, stores data), the docstring must not say "stub," "placeholder," or "no-op." Future readers (and code reviewers) will assume stubs are safe to remove or skip testing. Use accurate language: "Stores cost-basis state for use by `_update_position`."

**4. Duplicate-by-design should be commented.**
`_CostBasisTracker` and `_update_position` are intentional duplicates. Without a comment, the next reviewer will flag this as DRY violation. A one-line comment ("backtest package is kept self-contained — no cross-service imports") prevents the false finding and documents the architectural decision.
