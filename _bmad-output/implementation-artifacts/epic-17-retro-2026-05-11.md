## What Went Well

**1. Consumer-owns-interface pattern replicated cleanly across two Go services.**
17-1 (aggregator) established the `PubSubClient` interface pattern; 17-2 (candle-service) copied it with minimal friction. Architecture consistency across services paid off.

**2. Single Redis client reuse — no connection sprawl.**
Both pub/sub writers reused the existing `*goredis.Client`. The go-redis connection pool handles `PUBLISH` and `XADD` simultaneously. Clean and operationally simple.

**3. Gateway (17-3) is a well-designed, well-bounded service.**
Binary + text dual-channel over a single WebSocket, lastSnap for instant re-subscribe on connect, codec verified against `ws.ts` byte-for-byte. 11 tests covering all routing paths.

**4. Bot-service pub/sub thread-safety was correct from design.**
The `_pubsub_lock` + snapshot-then-iterate pattern and per-callback exception isolation were right from the start. Review found only lifecycle edge cases, not correctness bugs.

**5. Non-linear OFI time axis is a novel visualization designed from first principles.**
`N = max(1, round(clamp(|ofi|/rollingMean, 0.25, 4)))` compresses quiet microstructure and expands high-activity seconds. No prior art to copy; implemented cleanly from the AC spec.

## What We Should Improve

### Pattern 1: Missing `ctx.Err() == nil` guards — 3 of 5 stories
17-1, 17-2, and 17-3 all had review patches for missing shutdown-log guards. The project convention exists (see `stream.Write` and `ilp.Write`) but is not being applied to new code consistently.

**Action:** Add to CLAUDE.md — *"Every `slog.Warn`/`slog.Error` inside a goroutine error path requires `if ctx.Err() == nil` guard."*

### Pattern 2: Import/type-assertion friction in Go — 3 of 5 stories
Every Go story had at least one debug note: unused `context` import, `fmt.Sprint([]byte)` producing array notation, `Long256Column` signature mismatch. These are first-compile catches but add friction.

**Root cause:** `fmt.Sprint(msg interface{})` produces `"[72 101...]"` for `[]byte` — always use a type switch in fake clients. Worth noting in dev notes.

### Pattern 3: Double-logging on error paths — 17-2
Internal `WriteHeatmap` logged WARN on error AND `accWriter.Flush` in main.go also logged. Every failure emitted 2 lines. Fix: log in the inner writer only (single responsibility). 17-4 was designed correctly from the start.

### Pattern 4: Story checkbox [x] ahead of code — 17-5
The `gOverlay` / `gVolume` ordering fix was marked [x] in the story's review findings but was not actually applied to the code. Caught before commit in the next session.

**Convention:** Review findings are not [x] until the patch is committed and verified. The commit is the source of truth — not the story checkbox.

### Pattern 5: Concurrent fix analysis gap — 17-3
The "WritePump channel not closed" finding was triaged as a genuine patch, but implementation revealed a send-to-closed-channel panic race: `routeOrderbook` copies the target list, releases the hub lock, then iterates — creating a window after `close(c.send)`. The ctx-cancellation path is the correct and safe exit signal. Dismissed with explanation.

**Lesson:** When a concurrent data structure fix "feels right," trace the goroutine interleaving before implementing. 2 minutes of analysis prevents a subtle panic.

## Key Lessons

1. **`ctx.Err() == nil` before every error-path log in a goroutine** — project convention, add to CLAUDE.md.
2. **Review checkbox = patch committed + verified**, not patch decided. Story files are intentions; code is reality.
3. **Trace goroutine interleaving before applying concurrent fixes.** The WritePump race showed a "correct" fix was actually wrong.
4. **`fmt.Sprint([]byte)` trap** — use a type switch in all Go fake clients that capture `interface{}` payloads.
5. **NaN/Inf in `sort.Slice` breaks strict-weak-ordering** — both `sortedLevels` implementations need the guard. Candle-service got it in 17-2; aggregator's version should be audited.

## Technical Decisions

- **Gateway as separate Go module** — `gateway/` has its own `go.mod`. Correct: it has no shared packages with aggregator or candle-service and may need independent deployment.
- **lastSnap cache keyed by symbol** — Enables instant full-book replay on new subscriber without waiting for next tick. Unbounded growth acceptable for single-user local deployment; noted as D-17-3 future item.
- **`orderbook_mode = "none"` default for all existing strategies** — Explicit declaration with validation. Zero behaviour change; foundation for future microstructure strategies.
- **Non-linear OFI axis uses rolling mean over 20 values** — Short enough to track regime changes, long enough to smooth noise. `Math.max(1, ...)` ensures at least one column per second (prevents silent drops when OFI ≈ 0).
