## Challenges & Findings

### Process: Story files skipped for 1.2–1.7
Only Story 1.1 has a formal story file in `implementation-artifacts/`. Stories 1.2–1.7 were implemented directly from the epics document. This works for a solo project moving fast, but the dev-notes section in story files is where discovered gotchas and "why we did it this way" decisions land. Without them, institutional memory lives only in git commits.

**Impact for Epic 2:** Exchange adapter stories (2.1–2.5) have more protocol surface area and subtler design decisions. Story files become more valuable here.

### Technical: `time.Now()` calls in `exchange/kucoin/` violated the Epic 1 rule
The `make test-l1` grep check was scoped to the Epic 1 leaf packages (`orderbook/`, `reconnect/`, `gapdetector/`, `symbol/`, `backoff/`, `config/`). When KuCoin exchange code was written, it called `time.Now()` directly — a violation of the project context rule. This was caught and the Clock injection fix was applied before formal story creation, but the enforcement gap remains.

**Root cause:** The grep check scope wasn't extended to `internal/exchange/` because exchange/ is an Epic 2 concern. The rule applies everywhere in `internal/` regardless of epic.

### Process: Epic 2 exploratory work started before story creation
The Clock injection changes in `kucoin.go`, `token.go`, and the `go.mod` comment cleanup exist as uncommitted working-tree changes. The work is correct, but it runs ahead of the formal story cycle (no story file, no ATDD scaffold, no code review checkpoint).

---

## Key Insights

1. **Enforcement scope must match rule scope.** The `time.Now()` ban applies to all of `internal/` — the grep check must enforce it across all of `internal/`, not just the current epic's packages.
2. **Story files are cheap and pay off in Epic 2.** The dev-notes section is the right place for protocol-specific gotchas. Generate story files before devving, not after.
3. **Exploratory work is fine; capture it in the right story.** Pre-story clock injection is correct code. It should be committed cleanly before story 2.1 is created, so the story starts from a known-clean baseline.
